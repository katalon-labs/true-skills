# Contributing to True Skills

Thanks for improving the Katalon True Platform skills. One rule keeps this repo sane:

> **Edit `skills/` and `shared/references/` only. Everything else is generated.**

## How it works

`skills/<name>/SKILL.md` (plus its `references/*.md`) is the source for each workflow. Some reference files are shared by several skills. Their source lives in `shared/references/`. `scripts/sync-shared.mjs` copies each one into the skills that use it, and the copy starts with a `GENERATED` banner. Edit the source in `shared/references/`, never the copy.

The build script reads `skills/` and writes the native config for each supported agent:

| Output | Used by |
| --- | --- |
| `.agents/skills/` | Codex, Cursor, Copilot, Gemini CLI, OpenCode, Amp, Zed, Junie, Factory, Augment, Roo, Windsurf and Devin Desktop |
| `.kiro/skills/`, `.cline/skills/` | Kiro and Cline, which do not read `.agents/skills/` |
| `plugins/katalon-true-platform/` | Claude Code, Codex, and Cursor plugin, with the root marketplaces in `.claude-plugin/`, `.agents/plugins/`, and `.cursor-plugin/` |
| `plugin.json` and `mcp.json` | Agent Plugins standard manifest at the repo root |
| `.mcp.json`, `.cursor/mcp.json`, `.vscode/mcp.json`, `.github/mcp.json`, `.kiro/settings/mcp.json`, `.codex/config.toml`, `.continue/mcpServers/` | MCP config per client |
| `docs/connect.md` | Per-client MCP snippet table |
| `.continue/rules/` | Continue |
| `.github/copilot-instructions.md` | Copilot |
| `AGENTS.md` | Any agent that reads `AGENTS.md`. The build fails if it reaches 4 KB. |
| `apps/` and `app-assets/` | Kiro Crew app |

The build no longer writes `.cursor/rules/`, `.kiro/steering/`, `.windsurf/rules/`, `.clinerules/`, `.github/prompts/`, or `.github/skills/`. Each agent reads skills natively, so the copies only added size. The build deletes those folders if they exist.

Every generated text file carries a `GENERATED by scripts/build-adapters.mjs` banner. The skill mirrors (`.agents/skills/`, `.kiro/skills/`, `.cline/skills/`, and the plugin and Kiro Crew copies) are verbatim copies of `skills/`, plus an `agents/openai.yaml` file for Codex. Do not edit any of them. The next build wipes your change.

## Workflow

1. Edit a skill under `skills/`, or a shared file under `shared/references/`. Keep the body **agent-neutral**. Say "you" or "the agent", never a single product name.
2. Copy shared files into the skills, then check and rebuild:
   ```bash
   node scripts/sync-shared.mjs
   node scripts/validate-skills.mjs
   node scripts/build-adapters.mjs
   ```
   Requires Node >= 18. No dependencies to install.
3. Commit the sources and the regenerated files together.

## Writing standard

Write in short sentences. Use active voice and one term per meaning. Do not use em dashes. Name tools by bare name, for example `create_test_run`. Name the tenant URL as `<your.sub.domain>`. Keep each `SKILL.md` under 500 lines and move depth into `references/` with a "read this when" pointer.

## MCP tool names

The tool contract comes from the Katalon docs page "Katalon True Platform MCP Server". `docs/mcp-tools.json` lists every tool and the retired names. The validator fails when a skill names a retired tool or a tool that is not in the contract. To compare the contract with a live server, dump `tools/list` from an authenticated session and run `node scripts/check-mcp-live.mjs <tools-list.json>`.

## Release version

The version lives in one place: `PLUGIN_VERSION` in `scripts/build-adapters.mjs`. Every manifest, the marketplaces, and the Kiro Crew app read it from there. The skills carry the same number in `metadata.version`. To release, change the constant, update the skill metadata, add the `CHANGELOG.md` entry, and run the workflow above.

## Adding a new skill

1. Create `skills/<new-name>/SKILL.md` with YAML frontmatter and any `references/`. The frontmatter `name` must equal the folder name. Follow the description contract: 250 to 600 characters, third person, opens with what the skill does, then "Use when ...", names the adjacent skill it is not, and names each declared role.
2. Add an entry for `<new-name>` to the `INTERFACE` map and the `ORDER` array in `scripts/skills.config.mjs`. The `INTERFACE` entry needs `title`, `short`, `prompt`, and `roles`. `roles` is a subset of `ROLES` (`manual tester`, `automation tester`, `test lead`, `test manager`). Every role listed must appear verbatim in the skill's `description`, and every role named in the description must be listed. Declare a role only if a request phrased in role terms, naming no skill, should land here first. Use `roles: []` for a role-neutral skill. Keep the list to two or fewer unless the skill is the router.
3. Validate, rebuild, and commit:
   ```bash
   node scripts/validate-skills.mjs
   node scripts/build-adapters.mjs
   ```

The validator runs in CI before the build. It checks frontmatter, folder and `name` agreement, the description contract, the role contract, relative links inside each skill, shared-copy drift, the tool contract, leaked Katalon subdomains, and fetch-and-execute patterns.

## Adding a new agent

First check whether the agent reads `.agents/skills/` or its own skills folder. Most do, and then no new adapter is needed. For the MCP config, add one entry to the `CLIENTS` table in `scripts/build-adapters.mjs`. That one entry writes the shipped file (if any) and the snippet in `docs/connect.md`. Keep generation deterministic (no timestamps, sorted output) so the build stays idempotent. Then document the install path in `README.md`.

## Checks

CI runs these steps in order and fails if any one fails:

1. `node scripts/sync-shared.mjs`, then a clean-tree check.
2. `node scripts/validate-skills.mjs`.
3. `node scripts/build-adapters.mjs --check`, then a rebuild and a clean-tree check.
4. The ChatGPT package tests and build.

Two advisory jobs never block a merge: `claude plugin validate --strict` (the CLI may be missing on a runner) and `npx skills add ./ --list` (checks that the skills CLI finds every skill). Run the blocking steps locally before you push:

```bash
node scripts/sync-shared.mjs && node scripts/validate-skills.mjs && node scripts/build-adapters.mjs --check
```

## Conventions

- **No secrets, ever.** Skills must never instruct a user to paste passwords, tokens, cookies, JWTs, MFA codes, or OAuth callback URLs into chat.
- **State the limits of the MCP.** If the Katalon MCP cannot do something, the skill says so and offers the supported workaround.
- **One write rule.** Preview the creates, updates, and deletes, get one confirmation for the set, run them, then read back. Reads need no confirmation. Destructive tools need an explicit yes that names the target.
- **Use the canonical endpoint** `https://platform.katalon.io/mcp` in every config and example. Never commit a real workspace subdomain. `scripts/validate-skills.mjs` allows `platform` and fails on any other `*.katalon.io/mcp` host.
