# Contributing to True Skills

Thanks for improving the Katalon True Platform skills. The golden rule keeps this repo sane:

> **Edit `skills/` only. Everything else is generated.**

## How it works

`skills/<name>/SKILL.md` (plus its `references/*.md`) is the single source of truth for each workflow. The build script reads `skills/` and writes the native config for every supported agent:

- `plugins/katalon-true-platform/` - Claude Code + Codex plugin (and the root `.claude-plugin/` / `.agents/` marketplaces)
- `.cursor/rules/` - Cursor
- `.kiro/steering/` - Kiro
- `.github/skills/` + `.github/prompts/` + `.github/copilot-instructions.md` + `.vscode/mcp.json` - GitHub Copilot
- `.windsurf/rules/` - Windsurf
- `.clinerules/` - Cline
- `.continue/` - Continue
- `AGENTS.md` and `.mcp.json` - universal fallback

Every generated file carries a `GENERATED by scripts/build-adapters.mjs` banner, except the verbatim skill mirrors under `plugins/katalon-true-platform/skills/` and `.github/skills/`, which must stay byte-identical to `skills/`. Do not hand-edit any of them - your change will be wiped on the next build.

## Workflow

1. Edit a skill under `skills/`. Keep the body **agent-neutral** (say "you" or "the agent", never a single product name).
2. Regenerate:
   ```bash
   node scripts/build-adapters.mjs
   ```
   Requires Node >= 18. No dependencies to install.
3. Commit `skills/` **and** the regenerated files together.

## Adding a new skill

1. Create `skills/<new-name>/SKILL.md` with YAML frontmatter (`name`, `description`) and any `references/`. The frontmatter `name` must equal the folder name.
2. Add an entry for `<new-name>` to the `INTERFACE` map and the `ORDER` array in `scripts/skills.config.mjs`. The `INTERFACE` entry needs `title`, `short`, `prompt`, and `roles`. `roles` is a subset of `ROLES` (`manual tester`, `automation tester`, `test lead`, `test manager`); every role listed must appear verbatim in the skill's `description`, and every role named in the description must be listed. Declare a role only if a request phrased in role terms, naming no skill, should land here first. Use `roles: []` for a role-neutral skill, and keep the list to two or fewer unless the skill is the router.
3. Validate, rebuild, and commit:
   ```bash
   node scripts/validate-skills.mjs
   node scripts/build-adapters.mjs
   ```

`validate-skills.mjs` fails if a `skills/` folder is missing from `INTERFACE`/`ORDER` (or vice versa), if frontmatter is missing, if a folder name and its `name` disagree, if a real Katalon subdomain leaks into a skill body, if the role contract above is broken, if a description exceeds 1024 characters, or if a description contains a colon followed by a space (which breaks the unquoted YAML in `.cursor/rules/*.mdc`). It runs in CI before the build.

## Adding a new agent

Add a generation block to `scripts/build-adapters.mjs` that writes the agent's native format, then document the install path in `README.md`. Keep generation deterministic (no timestamps, sorted output) so the build stays idempotent.

## Checks

CI runs the validator, then the build, and fails if the working tree changes - i.e. if generated files are out of sync with `skills/`. Run both locally before pushing:

```bash
node scripts/validate-skills.mjs && node scripts/build-adapters.mjs && git diff --exit-code
```

## Conventions

- **No secrets, ever.** Skills must never instruct a user to paste passwords, tokens, cookies, JWTs, MFA codes, or OAuth callback URLs into chat.
- **Be honest about boundaries.** If the Katalon MCP can't do something, the skill says so and offers the supported workaround.
- Use the canonical endpoint `https://platform.katalon.io/mcp` in every config and example - never commit a real *workspace* subdomain. `scripts/validate-skills.mjs` allows `platform` and fails the build on any other `*.katalon.io/mcp` host.
